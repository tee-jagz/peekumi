# Sources

The rules in this system come from these sources. Where a rule is a design judgement for Peekumi, the section says so in its reason.

## Accessibility and platforms

- WCAG 2.2 Understanding documents: target size (2.5.8), dragging movements (2.5.7), focus not obscured (2.4.11), contrast (1.4.3), non-text contrast (1.4.11), use of colour (1.4.1), text spacing (1.4.12), reflow (1.4.10), status messages (4.1.3). https://www.w3.org/WAI/WCAG22/Understanding/
- Apple Human Interface Guidelines: accessibility, sheets, motion, dark mode, segmented controls, writing. https://developer.apple.com/design/human-interface-guidelines/
- Android accessibility: touch target size. https://support.google.com/accessibility/android/answer/7101858
- Material motion tokens. https://github.com/material-components/material-web/blob/main/tokens/versions/v0_192/_md-sys-motion.scss
- ARIA modal dialog pattern. https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/
- Web push on iOS. https://webkit.org/blog/13878/web-push-for-web-apps-on-ios-and-ipados/
- Viewport units and keyboard resize. https://web.dev/blog/viewport-units · https://developer.chrome.com/blog/viewport-resize-behavior

## Usability research

- Nielsen Norman Group: bottom sheets, progressive disclosure, response times, progress indicators, skeleton screens, error messages, notifications, animation duration, Liquid Glass. https://www.nngroup.com/articles/bottom-sheet/ · https://www.nngroup.com/articles/progress-indicators/ · https://www.nngroup.com/articles/indicators-validations-notifications/ · https://www.nngroup.com/articles/liquid-glass/
- Baymard: line length. https://baymard.com/blog/line-length-readability
- UXmatters: how people hold phones, touch accuracy. https://www.uxmatters.com/mt/archives/2013/02/how-do-users-really-hold-mobile-devices.php
