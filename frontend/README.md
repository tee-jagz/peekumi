# Frontend

The browser interface lets you explore repository structure, compare commits, follow dependencies, and inspect source from a phone. It renders the SVG map and the glass review panel using JavaScript, HTML and CSS.

- `app.js`: navigation, API requests, revision controls and the review panel.
- `ask.js`: scope-specific conversations that show each question at once, and explicit suggestion-to-draft actions.
- `workflow.js`: instructions (stored as comments), task preparation, run progress, agent evidence and verification.
- `model.js`: directory hierarchy, dependency aggregation and symbol diff filtering.
- `icons.js`: original rounded-stroke SVGs shared by object types, Git status, input/output indicators and icon-only controls. Control glyphs are decorative; each button carries its own accessible name and tooltip.
- `canvas.js`: SVG pan, pinch, zoom and card positioning.
- `select.js`: frosted menus in place of native select popups. Each `<select>` stays in the DOM as the value and change-event source; a button and listbox mirror it, with arrow, Home/End, Enter and Escape keys.
- `text.js`: safe Markdown rendering (paragraphs, lists, code, bold, italic) for answers, instructions and agent reports; builds DOM nodes and never parses HTML. Code spans the server resolved become links into the map.
- `peek.js`: Peek, the mascot, as an inline SVG whose state (idle, loading, thinking, success, error, empty) is animated by CSS; decorative and still under reduced motion.
- `index.html` and `style.css`: page structure and responsive appearance.

The phone sheet expands from a compact selection summary to half or full height using pointer or keyboard controls. Details, Source, Changes, Relations and Discussion are direct views, while the Ask/Instruction composer remains independent at the bottom. The dock follows the visual viewport when a phone keyboard opens. A single SVG graph remains the navigation surface; commit mini cards appear only in Time mode. The review sheet is frosted glass over the background gradient, and its buttons, tabs, rows and inputs are frosted with it; text inputs stay more opaque for legibility (native select popups follow the browser).

The frontend displays committed documentation as plain text. It does not execute code from inspected repositories. The backend embeds these assets when built.

The sheet follows pointer movement continuously and animates to a snap height on release; reduced-motion settings disable settling animation. Height changes preserve the graph DOM and transform. On a phone the map keeps its size while the sheet moves over it and resizes once when the sheet settles, so dragging does not re-lay-out the SVG map every frame. Only top-level glass surfaces use backdrop blur; elements inside a frosted surface use translucent tints. The canvas Legend explains Git colours and static relationship line styles, with text appropriate to the active colour lens.

Both Time and Diff follow the selected commit’s first parent by default, independent of the launch-time base. Selecting a base pins it while changing heads, refreshing or switching modes. The revision picker’s automatic option or “Use previous commit” clears that override. Explicit instruction/run inspection preserves its requested comparison range.

The compact phone sheet shows the selection description and available input/output types, without inspection controls. Inputs, outputs and fields are sideways-scrolling lines of name/type tokens that show declared types only; an Out row appears only for a declared return type or description. Half and full heights reveal navigation and complete declaration details, where every missing annotation is labelled explicitly. The map key lives in the floating canvas toolbar, opens upward over the graph and holds the Structure/Changes colour lens.

Selection status, review lists and the legend use shape-distinct coloured SVG icons without badge borders or backgrounds, and the contract uses entering/leaving arrows for inputs/outputs. Icons have accessible names and tooltips; the canvas legend explains them. Modified items use orange in both themes.

Tasks is an icon button in the header, so task state shows from every view without a badge. While an agent runs, Peek works in place of the icon and the button opens that task directly; when the agent finishes, Peek hops once and the icon returns accent-coloured for a ready task; a task that stopped partway with instructions open shows a drooping Peek on a warm tint until handled. The accessible label and tooltip say which. The task view shows the same Peek beside its heading, kept steady across polling redraws. Draft selection, a readable task preview, agent updates, results and review share one task view. Raw event streams and generated prompts are diagnostics. Unified diffs show before/after line numbers and hide Git transport headers. Reviewing records owner verification only; the interface explicitly distinguishes this from applying or deploying changes. Git ancestry determines whether task commits have been applied to the watched branch; deployment is not inferred from that status.

The line under the header title shows the viewed branch and the base → head comparison. It opens the comparison popover with the branch picker, head and base selectors, Use previous commit and refresh. The branch picker inspects local and already-fetched remote-tracking refs without checking out or fetching branches. History follows the selected branch and the selection survives reload in the URL. Completed tasks offer Explore changes, which opens the agent branch compared with the task's starting commit and shows a Back to task chip; Tasks shows its ready cue until review. Dispatch still targets the configured watched branch, identified in the task preview.

Dependency lines leave and arrive through a card's top or bottom edge, each at its own port, and finish with a straight run longer than the arrowhead, so the line meets the chevron along its axis; the chevron has one size whatever the line's width. A line that would cross another card goes around it through the row gaps and the nearest gap between columns, and lines going around to the same card merge into one trunk with one arrowhead. Every level (repository, folder and file) uses the same compact grid, and space opens only where a line needs it, in that card's column alone: a gap grows when a line turns through it, so columns are spaced independently. The gap between columns widens when neighbours in a row are connected, which then share a short straight arrow. Selecting a card emphasises its own connections by direction (accent for what it uses, teal for what uses it) and fades unrelated lines and cards; a selection without connections fades nothing. A modified declaration names its changed parts, signature, documentation or implementation, with small icons on its card and words in the sheet, Details and the Changes list.

Map cards use one neutral object-type icon beside the name, derived from adapter metadata. Folders, file groups, files/modules, classes/structs, functions/methods, interfaces/traits and enums have distinct icon families. Exact types remain available through accessible names and tooltips. Card tint carries Git status; redundant status dots are omitted from card titles and filename previews. Descriptions, counts and symbol-change previews remain intact.

Chrome stays minimal so the map keeps most of the phone screen. The header holds the repository name, the comparison line, icon Time/Diff and Tasks. On the map, Before/After floats in the top-left corner; Home and Up float bottom-left beside the Changes only, zoom, fit, reset and key controls, all in the same compact frosted shape. The current level is announced to assistive technology and named in the sheet. Directory cards summarise added, modified and removed counts plus the file total rather than truncated child-name chips; the card's accessible name includes the counts. Inspection views, Ask/Instruction, send, save and cancel are icon buttons; the active inspection view also shows its label. Popovers close on Escape, their close button or a pointer press elsewhere.

Peek shows complete text: a long summary or input/output list scrolls in whole lines, and fades its last line while more is available. Cards, lists, notices and task cards inside the sheet use the same frost; code, diffs and text inputs stay more opaque. Popovers and select menus use a denser glass so the map does not show through, and the map key is sized to the space above the floating toolbar.

The review sheet is built from three shared primitives: frosted section cards (`section()` in `app.js`), list cards whose rows show a status icon, title, muted detail and chevron, and a code box. Inspection tabs sit outside the scrolling content, and choosing a view only raises a peeking sheet; it never lowers a half or full sheet. In Source, the header stays put and the code box fills the remaining sheet height, scrolling inside itself. Details shows the selection's facts (kind, counts, path, analysis) with a single clear action. Relations rows read `from → to` with kind, status and before/after counts, without code-styled badges. File cards use icons for source, documentation, data/configuration, image, binary/restricted and other files: adapter-parsed files are source, and the rest follow their extension. The workflow poll redraws only when task data changed and a task view is open, so Source and Details keep their scroll position during agent runs. The panel's open view is `data-view`; `data-tab` belongs only to the tab buttons.

The existing comparison menu also selects registered local repositories and opens GitHub PR merge-base comparisons. Repository switching reloads the app to isolate source and workflow state. The installable PWA caches only the explicit app-shell asset allowlist; API data and source are never cached by its service worker. A new version announces itself in a frosted card with Peek (Later or Reload); if any box holds unsent text, Reload first says that text will be cleared while the saved Ask conversation and instructions stay. Offline uses the same card. Read-only devices have server-enforced restrictions and no agent composer.
